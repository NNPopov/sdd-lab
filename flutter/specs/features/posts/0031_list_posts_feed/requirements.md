# 0031 · list_posts_feed — Requirements

## Functional Requirements

| ID | Requirement |
|---|---|
| F1 | The screen loads the first page of posts automatically when first opened, without any user action. |
| F2 | The feed is accessible to anonymous visitors; no authentication token is required by the endpoint. |
| F3 | Each post card displays the post title, a stripped plain-text preview of the post body (max 100 chars), the publication date, and the author's username. |
| F4 | When the user scrolls to within 200 px of the bottom of the list, the next page loads automatically. |
| F5 | A loading spinner appears at the bottom of the list while an additional page is fetching. |
| F6 | When a load-more request fails, a Retry button appears at the bottom of the list; tapping it retries that page. |
| F7 | Pull-to-refresh discards the current list and reloads from page 1. |
| F8 | A full-screen loading indicator is shown while the very first page is loading. |
| F9 | When the initial load fails, a full-screen error message and a Retry button are shown; tapping Retry retries the initial load. |
| F10 | When the feed returns zero posts, an empty-state message is shown instead of a list. |
| F11 | Tapping "Open" on a post card navigates to that post's detail screen within the Posts tab, using the post's own username and id. |
| F12 | Authenticated users see a floating action button; anonymous users see no FAB. |
| F13 | Tapping the FAB navigates to the create-post screen using the authenticated user's own username. |
| F14 | When a PostDeleted event is published on the shared event bus, the corresponding post is removed from the visible list immediately, without a manual refresh. |
| F15 | A PostDeleted event received while the feed is not in the loaded state is silently ignored. |

## Non-functional Requirements

| ID | Requirement |
|---|---|
| N1 | `PaginatedPostsDto` resides in `_shared/data/dto/` and `PaginatedPosts` resides in `_shared/domain/entities/`; neither type exists inside `user_posts/`. |
| N2 | `PostsApiClient` imports `PaginatedPostsDto` from `_shared/data/dto/`, not from any slice subfolder. |
| N3 | `ListPostsAdapter` implements double catch: an inner `on DioException` catch maps HTTP status codes to typed `Failure` values; an outer `on Object` catch calls `AppLogger.error` with the error and stack trace, then returns `Failure.unknown()`. |
| N4 | `ListPostsState` is a sealed class generated by freezed, with variants: `initial`, `loading`, `loaded`, `error`. |
| N5 | `LoadMoreStatus` enum is defined in `list_posts_state.dart`; it is not imported from `user_posts_state.dart`. |
| N6 | `ListPostsCubit` subscribes to `PostEventBus` in its constructor and cancels the subscription in `close()`. |
| N7 | `ListPostsCubit.load()`, `refresh()`, and `loadMore()` accept no `username` parameter. |
| N8 | `ListPostsRoute.build` wraps `ListPostsScreen` in `BlocProvider(create: (_) => getIt<ListPostsCubit>())`. |
| N9 | No widget inside `list_posts/presentation/` calls `setState`; all state changes go through `ListPostsCubit`. |
| N10 | No file inside `list_posts/` imports from `user_posts/` or any other sibling slice; only `_shared/` cross-slice imports are permitted. |
| N11 | `ListPostTile` is defined inside `list_posts/presentation/widgets/`; it does not import `PostTile` from `user_posts/`. |
| N12 | The `_stripMarkdown` helper is defined locally within `list_posts/presentation/widgets/`; it is not imported from `user_posts/`. |
| N13 | `domain/ports/` and `domain/usecases/` files import only `dartz`, `freezed_annotation`, and pure Dart packages — no `flutter` or `dio` imports. |
| N14 | `hasMore` is computed as `page * itemsPerPage < totalCount`. |
| N15 | `ListPostsRoute` is registered in the router without an auth guard. |
| N16 | All UI strings in `list_posts/` are referenced via `context.t` (slang); no string literals appear in widget build methods. |
| N17 | No new package is added to `pubspec.yaml` as part of this slice. |

## Out of scope

- Filtering or sorting the global post feed.
- Full-text search within the feed.
- Navigating between pages via explicit page-number controls.
- Displaying media attachments (images, video) inside the post tile.
- Editing or deleting a post directly from the feed list.
- Any behavioral change to the `user_posts` slice beyond updating import paths after the shared-entity migration.
- Changes to authentication or anonymous-user registration flows.
