# Plan — 0053 user_posts_create_post_route_to_user_id

> Implementation spec for the third and final posts route-migration slice. Sources:
> `prd.md` (this folder), `docs/adr/0002-posts-route-migration-fine-grained-slices.md`,
> `CONTEXT.md`, and the already-migrated slices 0051/0052 + users slice 0050.

---

## 1. Header

Migrate the **by-author** posts surface from `{username}` to `{user_id}`: the
`user_posts` (list-by-author) and `create_post` (publish) verticals. The `user_posts`
route becomes keyed by `int userId`; the author's `username` **handle** is carried as a
**non-path display argument** for the `@username` AppBar title (per ADR-0002). The
`create_post` route becomes keyed by `int userId` (no handle needed — it displays none).

This is a **pure identifier change** (no behavior, no UI string, no request-body change).
It is the last slice of the posts migration: after it, no posts route is addressed by a
handle and the three remaining `// Posts routes are not migrated` bridges (app shell,
user-details, users-list) are removed.

## 3. API

Base: `http://127.0.0.1:8000/api/v1` (relative paths on `PostsApiClient`). Both routes
require `Authorization: Bearer <token>`.

### getUserPosts (list by author)

```
BEFORE: GET /{username}/posts?page={p}&items_per_page={n}   @Path('username') String
AFTER:  GET /{user_id}/posts?page={p}&items_per_page={n}     @Path('user_id') int
Response 200: PaginatedPostsDto  (unchanged shape)
```

Errors (unchanged mapping in `UserPostsAdapter`):
- `404` — user/author not found → `Failure.notFound()`.
- `≥500` — `Failure.server(statusCode)`.
- connection/other `DioException` — `Failure.network(message)`.
- any other exception → catch-all `logger.error` + `Failure.unknown()`.

### createPost (publish)

```
BEFORE: POST /{username}/post   @Path('username') String   @Body CreatePostRequestDto
AFTER:  POST /{user_id}/post     @Path('user_id') int        @Body CreatePostRequestDto (UNCHANGED)
Response 200: PostDto  (existing adapter ignores it → returns Right(null))
```

Server-side rule: a user may create a post **only as themselves** (the backend keys the
route by the author id). The client mirrors this in `CreatePostUseCase` *before* the call.

Errors (unchanged mapping in `CreatePostAdapter`):
- `401` → `Failure.unauthorized`; `403` → `Failure.forbidden`; `422` →
  `MessageValidationFailure`; connection error → `Failure.network`; else
  `Failure.server(statusCode)`; catch-all → `logger.error` + `Failure.unknown()`.

## 5. What to do

Work bottom-up by layer. Both verticals are independent — do `user_posts` fully, then
`create_post` fully, then routing + call sites.

### 5.1 `_shared` — PostsApiClient (CODEGEN)

In `posts_api_client.dart`, change only these two methods:

```dart
@GET('/{user_id}/posts')
Future<PaginatedPostsDto> getUserPosts(
  @Path('user_id') int userId, {
  @Query('page') required int page,
  @Query('items_per_page') required int perPage,
});

@POST('/{user_id}/post')
Future<PostDto> createPost(
  @Path('user_id') int userId,
  @Body() CreatePostRequestDto body,
);
```

Leave `getPosts`, `getPost`, `patchPost`, `deletePost`, `eraseDbPost`, `getPendingPosts`,
`moderatePost`, `revisePost`, `getModerationLog` untouched.

### 5.2 `user_posts` vertical — DOMAIN → DATA → APPLICATION

1. **Port** (`user_posts_port.dart`): `required String username` → `required int userId`.
2. **Use-case** (`user_posts_usecase.dart`): same rename; it is a pure pass-through to the
   port — `_port(userId: userId, page: page, perPage: perPage)`.
3. **Adapter** (`user_posts_adapter.dart`): rename the named param to `int userId`; call
   `_api.getUserPosts(userId, page: page, perPage: perPage)`. **Preserve** the existing
   double-`try`/`catch`, the paginated→`PaginatedPosts` mapping (including
   `_parseStatus`), the `_mapHttp` (404 / ≥500 / network), and the catch-all
   `logger.error` + `Failure.unknown()`.
4. **Cubit** (`user_posts_cubit.dart`): change `load`, `refresh`, and `loadMore` to take
   `int userId` instead of `String username`. The `PostDeleted` event handling and the
   `_pageSize`, paging, and `LoadMoreStatus` logic are unchanged.

### 5.3 `user_posts` presentation — page + screen (CODEGEN for the page)

**`user_posts_route.dart`** — `UserPostsPage`:

```dart
@RoutePage()
class UserPostsPage extends StatelessWidget {
  const UserPostsPage({
    @PathParam('user_id') required this.userId,
    required this.username,           // non-path display arg (the handle, for the title)
    super.key,
  });

  final int userId;
  final String username;

  @override
  Widget build(BuildContext context) => BlocProvider(
        create: (_) => getIt<UserPostsCubit>(),
        child: UserPostsScreen(userId: userId, username: username),
      );
}
```

> **WHY** `username` is required and non-path: ADR-0002 — keep the handle out of the URL
> but preserve the `@username` title for in-app navigation (including authors with zero
> posts, where the loaded list yields no handle). Every in-app `UserPostsRoute`
> construction supplies it (step 5.6).

**`user_posts_screen.dart`** — `UserPostsScreen({required int userId, required String
username})`:

- `load`/`refresh`/`loadMore` calls now pass `widget.userId` (not `widget.username`).
- AppBar title stays `t.posts.userPosts.title(username: widget.username)` — the **handle**,
  unchanged.
- FAB visibility (ownership) flips to identity:
  `final isOwner = authState is AuthAuthenticated && authState.currentUser?.id == widget.userId;`
- FAB navigation: `CreatePostRoute(userId: widget.userId)` (was `username:`).
- Post tiles already build `PostDetailsRoute(userId: posts[index].createdByUserId, id: …)`
  (migrated in 0051) — **leave unchanged**.

### 5.4 `create_post` vertical — entity → use-case → adapter

1. **Entity** (`new_post_data.dart`): `final String username` → `final int userId`; rename
   the constructor param accordingly. Keep `title`, `text`, `mediaUrl`.
2. **Use-case** (`create_post_usecase.dart`): flip the ownership guard from handle to id:

   ```dart
   final currentUser = _authCubit.currentUser;
   if (currentUser == null || currentUser.id != data.userId) {
     return const Left(Failure.forbidden(message: 'Cannot post as another user'));
   }
   return _port(data);
   ```

   > **WHY** `currentUser.id != data.userId`: `CONTEXT.md` lists exactly this comparison as
   > an **identity** check (`currentUser.username != data.username` → migrate). Same
   > `Failure.forbidden`, same message.
3. **Adapter** (`create_post_adapter.dart`): call `_api.createPost(data.userId,
   CreatePostRequestDto(title: …, text: …, mediaUrl: …))`. The body and the `_mapHttp`
   (401/403/422 + network/server) and catch-all `logger.error` are **unchanged**.
4. **Cubit** (`create_post_cubit.dart`): **no change** — `submit(NewPostData)` is unchanged.

### 5.5 `create_post` presentation — page + screen (CODEGEN for the page)

**`create_post_route.dart`** — `CreatePostPage`: `@PathParam('username') String username`
→ `@PathParam('user_id') int userId`; pass `userId` to `CreatePostScreen`.

**`create_post_screen.dart`** — `CreatePostScreen({required int userId})`. In `_onSubmit`,
build `NewPostData(userId: widget.userId, title: …, text: …, mediaUrl: …)`. No handle is
displayed (the AppBar title is the static `t.posts.createPost.title`), so no display arg.

### 5.6 Routing + cross-feature call sites (CODEGEN for `app_router`)

**`app_router.dart`** — change three path strings (`:username` → `:user_id`):

| Tab | before | after |
|---|---|---|
| Users | `user/:username/posts` | `user/:user_id/posts` |
| Users | `user/:username/posts/create` | `user/:user_id/posts/create` |
| Posts | `:username/posts/create` | `:user_id/posts/create` |

Leave the already-migrated single-post paths (`:user_id/posts/:id`, `.../edit`) and the
non-username paths (feed, pending, `post_uuid`) untouched.

**`UserPostsRoute` constructions** → pass `userId` + `username`, remove the bridge comments:

- `app_shell_screen.dart` (myPosts menu): `UserPostsRoute(userId: currentUser.id, username: currentUser.username)`.
- `user_details_screen.dart` (Posts action): `UserPostsRoute(userId: user.id, username: user.username)`.
- `users_screen.dart` (per-row): `UserPostsRoute(userId: u.id, username: u.username)`.

**`CreatePostRoute` constructions** → pass `userId`:

- `list_posts_screen.dart` (feed FAB): `CreatePostRoute(userId: authState.currentUser!.id)`.
- `user_posts_screen.dart` (FAB): `CreatePostRoute(userId: widget.userId)` (done in 5.3).

> These are route-class constructions; the route classes live in `core/routing`, so the
> `users` feature does **not** import the `posts` feature — no layering rule is broken.

### 5.7 Localization

**None.** No new or changed UI strings. `t.posts.userPosts.title(username:)` keeps taking
the handle string; `t.posts.createPost.*` is unchanged.

- ❌ Do **not** touch `getPost`/`patchPost`/`deletePost`/`eraseDbPost` (0051/0052) or the

- ❌ Do **not** change the `CreatePostRequestDto` body, the create form/validation, the
  markdown preview, the pull-to-refresh, the paging logic, or any failure message.
- ❌ Do **not** add a display `username` arg to `CreatePostRoute` — the create screen shows
  no handle.
- ❌ Do **not** import the `posts` feature from the `users` feature (or vice-versa); only
  construct the shared route classes from `core/routing`.
- ❌ Do **not** introduce new dependencies, new states, or new screens. This is a pure
  identifier migration.
