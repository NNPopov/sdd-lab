# 0042 · arch_violations_fix — Requirements

## Functional Requirements

| ID | Requirement |
|---|---|
| F1 | When a form Cubit emits a `ValidationFailure`, the form screen renders the error message below the submit button. |
| F2 | The error message text is taken from `ValidationFailure.fieldErrors.values.firstOrNull`, covering both FastAPI per-field errors and general single-message errors stored under the `'error'` key. |
| F3 | When the user edits any text field on a form screen that is displaying a server validation error, the error disappears immediately. |
| F4 | Form screen `TextFormField` validators perform only client-side checks (empty field, format); server-side error messages are not returned by validators. |
| F5 | When a form Cubit listener receives `ValidationFailure`, no snackbar is shown; display is handled entirely by the builder. |
| F6 | When a form Cubit listener receives `PermissionDenied`, a snackbar with a permission-denied message is shown. |
| F7 | When a form Cubit listener receives `ConflictFailure`, a snackbar with the server-provided conflict message is shown. |
| F8 | When a form Cubit emits a success state, the screen pops and shows a success snackbar. |
| F9 | When a server validation error is visible and the user re-submits the form (client validation passes), the old error disappears through the normal `Idle → Submitting` state transition; no explicit clear is needed. |
| F10 | When a server validation error is visible and the user re-submits the form (client validation fails), the server error remains visible alongside the client-side field errors. |
| F11 | `AssignModeratorButton` displays an "Assign" label when given `isModerator: false`. |
| F12 | `AssignModeratorButton` displays a "Revoke" label when given `isModerator: true`. |
| F13 | On `AssignModeratorSuccess`, `AssignModeratorButton` invokes its `onToggled` callback with the new moderator status boolean. |
| F14 | On `AssignModeratorError`, `AssignModeratorButton` shows a snackbar and does not invoke `onToggled`. |
| F15 | After `onToggled` is invoked, `UserDetailsScreen` reflects the updated moderator status without reloading user data from the network. |
| F16 | A moderator assignment or revocation does not re-trigger `GetUserTierCubit.load()`. |
| F17 | `AppRouter.routes` does not produce a SLOC ALARM when `dart_code_linter:metrics analyze` is run after the change. |
| F18 | The complete route tree remains in a single, co-located, readable location in `AppRouter`. |

## Non-functional Requirements

| ID | Requirement |
|---|---|
| N1 | `core/auth/domain/entities/auth_session.dart` and `current_user.dart` must not import any `package:flutter/*` package; `@immutable` is provided by `package:meta/meta.dart`. |
| N2 | No widget that owns a Cubit uses `setState` to manage reactive state. |
| N3 | `CreateTierState` and `CreateUserState` sealed hierarchies use `idle` (not `initial`) as the name of the starting subtype; both are generated by `freezed`. |
| N4 | `CreateTierCubit` and `CreateUserCubit` each expose a `clearError()` method that emits the `Idle` state. |
| N5 | `AssignModeratorButton` and its inner widget are `StatelessWidget`s; no `State` subclass exists in the file. |
| N6 | `moderator_contract/presentation` does not import `user_details/application`; the `onToggled` callback is the only communication channel between the two slices. |
| N7 | `UserDetailsCubit.updateIsModerator(bool)` is a no-op when the current state is not `UserDetailsLoaded`. |
| N8 | The `AppRouter` route tree field is `late final` (instance, not static) because it references constructor-injected instance fields `authGuard` and `permissionCubit`. |
| N9 | All new and modified UI strings are provided via slang keys; no hardcoded strings appear in widget code. |
| N10 | After any `@freezed` state file is changed, `dart run build_runner build --delete-conflicting-outputs` is run before further compilation. |
| N11 | After any i18n JSON file under `lib/core/i18n/i18n/` is changed, `dart run slang` is run. |
| N12 | `dart format .` produces no diff and `dart analyze` reports no warnings after all changes are applied. |
| N13 | Each modified Cubit and widget has test coverage for all new behavioral paths introduced by this slice (see plan.md Testing section). |

## Out of scope

- Decomposition of large `build()` methods in `PostDetailsScreen`, `CreateUserScreen`, and `UserDetailsScreen` (CC/SLOC ALARMs for those methods).
- Addressing the 26 WARNING-level CC metrics in `_mapHttp` / `_parseValidation` adapter methods.
- Changing `ValidationFailure.fieldErrors` from `Map<String, String>` to a single `String message` field.
- Any changes to server API contracts or adapter response-parsing logic.
