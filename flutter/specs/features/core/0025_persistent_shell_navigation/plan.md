# Plan: Persistent Shell Navigation (0025)

## Overview

Restructure the `auto_route` navigation graph so that the app shell (AppBar + tab
bar) is always visible during deep navigation. Each of the three main tabs becomes an
independent nested stack navigator. The back-arrow appears automatically via
`AutoLeadingButton`. After destructive deletes the correct list page is restored
without replacing the shell.

## Implementation steps

### Step 1 — Three tab wrapper route files

Create `lib/core/routing/tabs/users_tab_route.dart`:

```dart
import 'package:auto_route/auto_route.dart';
import 'package:flutter/widgets.dart';

@RoutePage()
class UsersTabPage extends StatelessWidget {
  const UsersTabPage({super.key});

  @override
  Widget build(BuildContext context) => const AutoRouter();
}
```

Repeat for `PostsTabPage` (`posts_tab_route.dart`) and `TiersTabPage`
(`tiers_tab_route.dart`). These are thin wrappers — zero business logic, zero DI.

---

### Step 2 — Restructure `app_router.dart`

Import the three new tab route files. Remove all route imports that are moving into
nested children (they stay imported — they are still referenced in the children lists).

Rewrite `get routes` so that:

1. The top-level list contains **only** `LoginRoute` and `AppShellRoute`.
2. `AppShellRoute`'s children reference **the three tab wrapper pages**, not the list
   pages directly.
3. Each tab wrapper page has its own `children` list, as shown below.

```dart
AutoRoute(
  page: AppShellRoute.page,
  path: '/',
  initial: true,
  children: [
    // ── Users tab ──────────────────────────────────────────────
    AutoRoute(
      page: UsersTabRoute.page,
      path: '',
      initial: true,
      children: [
        AutoRoute(page: UsersRoute.page, initial: true, path: ''),
        AutoRoute(page: CreateUserRoute.page, path: 'users/new'),
        AutoRoute(
          page: UserDetailsRoute.page,
          path: 'user/:username',
        ),
        AutoRoute(
          page: EditUserRoute.page,
          path: 'user/:username/edit',
          guards: [authGuard],
        ),
        AutoRoute(
          page: UserPostsRoute.page,
          path: 'user/:username/posts',
        ),
        AutoRoute(
          page: CreatePostRoute.page,
          path: 'user/:username/posts/create',
          guards: [authGuard],
        ),
        AutoRoute(
          page: PostDetailsRoute.page,
          path: 'user/:username/posts/:id',
        ),
        AutoRoute(
          page: EditPostRoute.page,
          path: 'user/:username/posts/:id/edit',
          guards: [authGuard],
        ),
      ],
    ),

    // ── Posts tab ──────────────────────────────────────────────
    AutoRoute(
      page: PostsTabRoute.page,
      path: 'posts',
      children: [
        AutoRoute(page: ListPostsRoute.page, initial: true, path: ''),
        AutoRoute(
          page: PostDetailsRoute.page,
          path: ':username/posts/:id',
        ),
        AutoRoute(
          page: EditPostRoute.page,
          path: ':username/posts/:id/edit',
          guards: [authGuard],
        ),
        AutoRoute(
          page: CreatePostRoute.page,
          path: ':username/posts/create',
          guards: [authGuard],
        ),
      ],
    ),

    // ── Tiers tab ──────────────────────────────────────────────
    AutoRoute(
      page: TiersTabRoute.page,
      path: 'tiers',
      guards: [
        authGuard,
        PermissionGuard({Permission.manageTiers}, permissionCubit),
      ],
      children: [
        AutoRoute(page: ListTiersRoute.page, initial: true, path: ''),
        AutoRoute(
          page: TierDetailsRoute.page,
          path: ':name',
          guards: [
            authGuard,
            PermissionGuard({Permission.manageTiers}, permissionCubit),
          ],
        ),
        AutoRoute(
          page: CreateTierRoute.page,
          path: 'new',
          guards: [
            authGuard,
            PermissionGuard({Permission.manageTiers}, permissionCubit),
          ],
        ),
        AutoRoute(
          page: EditTierRoute.page,
          path: ':name/edit',
          guards: [
            authGuard,
            PermissionGuard({Permission.manageTiers}, permissionCubit),
          ],
        ),
      ],
    ),
  ],
),
```

**IMPORTANT — PostDetailsRoute appears in two tabs.** This is intentional: the same
`PostDetailsPage` class is declared as a child in both `UsersTabRoute` and
`PostsTabRoute`. The path segments differ between the tabs (one is reached via
`user/:username/posts/:id` under the Users tab root, the other via a shorter segment
under the Posts tab root). Cross-tab deep-link ambiguity is **out of scope** (see PRD).

**IMPORTANT — `CreateUserRoute` path.** The existing router had no explicit path for
`CreateUserRoute`. Assign it `'users/new'` within the Users tab. No existing code
navigates to `CreateUserRoute` by URL — it is pushed programmatically — so no other
file is affected.

### Step 3 — Modify `app_shell_screen.dart`

Two changes only:

**3a. Update `AutoTabsRouter` routes list** to reference the three new tab page routes:

```dart
AutoTabsRouter(
  routes: const [UsersTabRoute(), PostsTabRoute(), TiersTabRoute()],
  ...
)
```

**3b. Add `AutoLeadingButton` as the `leading` of the `AppBar`:**

```dart
appBar: AppBar(
  leading: const AutoLeadingButton(),   // ← add this line
  title: Text(context.t.app.title),
  bottom: _AppNavBar(tabsRouter: tabsRouter),
  actions: const [LocaleSelectorButton(), _AuthAppBarAction()],
),
```

`AutoLeadingButton` (from `package:auto_route/auto_route.dart`) reads the nearest
`AutoRouterDelegate` — which is the active tab's inner `AutoRouter` — and shows a
back-arrow when `canPop()` is true. It shows nothing at the root of each tab. No
per-page change is needed.

**No other changes to `app_shell_screen.dart`.** The tab-index logic, the
superuser-guard on the Tiers tab, and the logout redirect all stay exactly as-is.

### Step 4 — Delete navigation audit

After the restructuring, `context.router` within any page that lives inside a tab
wrapper refers to **that tab's inner `AutoRouter`**, not to the root router. This
means:

| Button | Current navigation call | After restructuring |
|---|---|---|
| `DeleteAccountButton` | `context.router.replaceAll([UsersRoute()])` | Still correct — replaces UsersTab's stack with the users list; shell stays |
| `DeletePostButton` | `context.router.pop()` | Still correct — pops within whichever tab stack the page lives in |
| `DeleteTierButton` | `context.router.pop()` | Still correct — pops within TiersTab's stack |

**No changes required** in any delete presentation file. Verify by inspection that
the calls above use `context.router` (not `context.router.root`) — if they do,
leave them as-is.

## What NOT to do

- **Do not** add business logic, DI provision, or BlocProvider to the three tab
  wrapper pages. They must remain empty `AutoRouter()` wrappers.
- **Do not** add `guards` to the tab wrapper routes themselves. Guards stay on
  individual child routes, exactly as today.
- **Do not** change the `_AppNavBar` tab-switching logic, the superuser check, or
  the `listenWhen` logout redirect. These operate on `tabsRouter.activeIndex` which
  is stable after this refactor.
- **Do not** use `context.router.root.replaceAll(...)` in any delete button — that
  would replace the entire app stack and remove the shell.
- **Do not** change the `tab_route` comment index used in `AppShellScreen`'s
  `listenWhen: ... tabsRouter.activeIndex == 2`. Tiers tab remains at index 2.
- **Do not** alter any slice outside `core/routing/`. If a compile error in a slice
  file arises from the route tree change, fix only the import — do not refactor the
  slice.
- **Do not** change URLs for existing routes without explicit confirmation; paths
  in tab children must be designed so the composite path matches the current URL
  (use relative child paths or auto_route's absolute-path prefix `/` where needed).
