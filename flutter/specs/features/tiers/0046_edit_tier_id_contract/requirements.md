# 0046 · edit_tier_id_contract — Requirements

## Functional Requirements

| ID | Requirement |
|---|---|
| F1 | The API client sends `PATCH /tier/{id}` where `{id}` is an integer path parameter. |
| F2 | The request body contains the field `"name"` (not `"new_name"`) with the new tier name. |
| F3 | `EditTierPage` accepts an integer path parameter `id` and a string query parameter `name`. |
| F4 | The edit form is pre-populated with the current tier name supplied via the `name` query parameter. |
| F5 | On successful edit, the screen pops and returns the updated name string to the caller. |
| F6 | The tier-details screen passes both `tierId` (int) and `tierName` (String) when navigating to `EditTierRoute`. |
| F7 | On success, the screen displays a snackbar with the localized success message. |
| F8 | On a 404 response from the server, the screen displays a snackbar with the localized "not found" error message. |
| F9 | On a 403 response or a permission-denied failure, the screen displays a snackbar with the localized "permission denied" error message. |
| F10 | The Save button is disabled and replaced by a loading indicator while a submission is in progress. |
| F11 | When the caller is not a superuser, the use-case returns `Left(PermissionDenied)` immediately without invoking the adapter. |

## Non-functional Requirements

| ID | Requirement |
|---|---|
| N1 | `EditTierData` is a pure Dart class with no Flutter or Dio imports; it resides in `domain/entities/`. |
| N2 | `EditTierRequestDto` is a sealed `freezed` class; its `name` field carries no `@JsonKey` annotation so the serialised key matches the Dart field name. |
| N3 | `EditTierAdapter` follows the double-catch pattern: an inner `on DioException catch` block maps HTTP errors, and an outer `catch (e, st)` block logs via `AppLogger.error` and returns `Left(Failure.unknown())`. |
| N4 | No exception escapes `EditTierAdapter.call`; the outer catch-all never swallows an error silently (logging is mandatory). |
| N5 | All UI strings in `EditTierScreen` are accessed via `slang` translation keys; no hardcoded strings are permitted. |
| N6 | `EditTierScreen` uses no `setState`; all state management is delegated to `EditTierCubit`. |
| N7 | The `edit_tier` slice does not import from any sibling slice of the `tiers` feature; only `_shared/` is allowed. |
| N8 | `EditTierState` is a sealed class generated by `freezed`. |
| N9 | After `TiersApiClient.patchTier` path and param type are changed, Retrofit code-gen (`build_runner`) is re-run to regenerate `tiers_api_client.g.dart`. |
| N10 | The `auto_route` path for `EditTierRoute` in `app_router.dart` is `':id/edit'` (integer segment). |
| N11 | Only the single navigation call in `tier_details_screen.dart` is updated outside the `edit_tier` slice; no other file in the `tier_details` slice is modified. |
| N12 | `EditTierCubit.submit` passes `isSuperuser` to the use-case and emits `EditTierState.success(newName: data.name)` only when the use-case returns `Right(unit)`. |

## Out of scope

- Changes to the `tier_details` slice beyond the single `EditTierRoute` navigation call.
- Changes to the `delete_tier` slice.
- Renaming any tier DTO fields beyond `new_name` → `name` in the request body.
