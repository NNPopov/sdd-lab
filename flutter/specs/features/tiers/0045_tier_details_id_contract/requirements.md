# 0045 · tier_details_id_contract — Requirements

## Functional Requirements

| ID | Requirement |
|---|---|
| F1 | The system shall retrieve tier details by integer `id` via `GET /tier/{id}`. |
| F2 | The tier details route URL shall use a numeric segment (`tiers/:id`) so that bookmarked URLs remain stable across tier renames. |
| F3 | The tier details route shall also accept a `name` query parameter used for immediate display while the API response loads. |
| F4 | The AppBar title shall display `tierName` (from the query parameter) while the state is initial or loading. |
| F5 | The AppBar title shall update to `tier.name` from the loaded API response once the detail state is `TierDetailsLoaded`. |
| F6 | A spinner shall be shown in the screen body while tier details are loading. |
| F7 | The full tier detail card (name, id, creation date) shall be shown when the state is `TierDetailsLoaded`. |
| F8 | A "not found" message shall be shown when the state is `TierDetailsError` with `NotFoundFailure`. |
| F9 | A "permission denied" message shall be shown when the state is `TierDetailsError` with `PermissionDenied`. |
| F10 | A generic error message with a retry button shall be shown for all other `TierDetailsError` failures. |
| F11 | The retry button shall reload tier details using the original `tierId` (integer). |
| F12 | For superusers, an edit button shall be visible on the tier details screen; tapping it opens the edit screen for the current tier name. |
| F13 | After a successful rename, the tier details screen shall refresh in place with the same `tierId` and the new tier name (AppBar and URL both update). |
| F14 | For superusers, a delete button shall be visible on the tier details screen. |
| F15 | The list-tiers screen shall navigate to `TierDetailsRoute` passing both `tierId` (integer) and `tierName` (string). |
| F16 | The use-case shall return `Left(PermissionDenied)` immediately when the caller lacks the `manageTiers` permission, without calling the port. |
| F17 | The adapter shall map a 401 response to `Left(UnauthorizedFailure)`, 403 to `Left(ForbiddenFailure)`, 404 to `Left(NotFoundFailure)`, and any other HTTP error to `Left(ServerFailure)`. |
| F18 | The adapter shall return `Left(UnknownFailure)` for any non-HTTP exception and log the error via `AppLogger`. |

## Non-functional Requirements

| ID | Requirement |
|---|---|
| N1 | The `GetTierPort` interface signature is `Future<Either<Failure, TierDetail>> call(int id)`. |
| N2 | The `GetTierAdapter` implements `GetTierPort` with a two-level catch: inner `on DioException` for HTTP mapping, outer `catch (e, st)` with `_logger.error` for all other exceptions. |
| N3 | The `TierDetailsState` is a sealed class generated by freezed with four variants: `initial`, `loading`, `loaded`, `error`. |
| N4 | The `TierDetailsCubit` stores no identifier; callers (`TierDetailsScreen`) are responsible for supplying `tierId` on every `load` and `retry` call. |
| N5 | The `TierDetailsPage` route page accepts `@PathParam('id') int tierId` and `@QueryParam('name') String tierName` via auto_route code-gen. |
| N6 | `domain/` does not import any `package:flutter/*`, `package:dio/*`, or package outside `dartz`/`freezed`/pure Dart. |
| N7 | `tier_details` slice does not import any other slice of the `tiers` feature except through `_shared/`. |
| N8 | No UI string is hardcoded; all user-visible text uses slang translation keys. |
| N9 | After changing `tiers_api_client.dart` or `tier_details_route.dart`, code-gen (`build_runner build`) must be re-run to keep generated files in sync. |
| N10 | The `getTier` method in `TiersApiClient` uses `@Path('id') int id` with the route template `/tier/{id}`; only this method is changed — `patchTier` and `deleteTier` remain name-based. |
| N11 | `TierDetailsScreen` uses `BlocBuilder<TierDetailsCubit, TierDetailsState>` for AppBar title rendering; no `setState` is used in a widget that has a Cubit. |

## Out of scope

- Changes to the `edit_tier` slice (covered by PRD 0046).
- Changes to the `delete_tier` slice (covered by PRD 0047).
- Changing the list-tiers paginated endpoint or its response shape.
- Any changes to the `Tier` shared entity.
