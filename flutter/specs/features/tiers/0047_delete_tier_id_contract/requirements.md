# 0047 · delete_tier_id_contract — Requirements

## Functional Requirements

| ID | Requirement |
|---|---|
| F1 | The delete-tier API call uses `DELETE /tier/{id}` with an integer `id` as the path parameter; the old `DELETE /tier/{name}` path is no longer used. |
| F2 | The delete button is visible only when the authenticated user is a superuser; it is hidden for all other roles. |
| F3 | Pressing the delete button shows a confirmation dialog that displays the tier name so the user can verify the correct tier is about to be deleted. |
| F4 | Confirming the dialog calls `confirmAndDelete(tierId)` with the integer tier id. |
| F5 | Cancelling the dialog returns the cubit to the initial state without performing a deletion. |
| F6 | On a successful deletion (204), a success snackbar is shown and the screen is popped. |
| F7 | When the server returns 404, a "not found" snackbar is shown and the screen is popped. |
| F8 | When the server returns 403, a "forbidden" error snackbar is shown; the screen is not popped. |
| F9 | When the server returns 401, an "unauthorized" error snackbar is shown; the screen is not popped. |
| F10 | When an unexpected error occurs, a generic error snackbar is shown; the screen is not popped. |
| F11 | While deletion is in progress, the delete button displays a loading spinner and is non-interactive. |
| F12 | The permission guard in the use-case returns `Left(Failure.permissionDenied())` immediately when `isSuperuser` is false, without calling the port. |

## Non-functional Requirements

| ID | Requirement |
|---|---|
| N1 | `TiersApiClient.deleteTier` is annotated `@DELETE('/tier/{id}')` with `@Path('id') int id`; the old `@Path('name') String name` annotation is removed. |
| N2 | `DeleteTierPort.call` signature is `Future<Either<Failure, Unit>> call(int id)`. |
| N3 | `DeleteTierUseCase.call` named parameter is `required int id` (renamed from `required String name`). |
| N4 | `DeleteTierCubit.confirmAndDelete` parameter is `int tierId` (type changed from `String tierName`). |
| N5 | `DeleteTierButton` exposes both `tierId: int` and `tierName: String` as required constructor parameters; `tierId` is passed to the cubit, `tierName` is passed to the confirmation dialog. |
| N6 | `DeleteTierAdapter.call` follows the double-catch pattern: inner `on DioException catch (e)` for HTTP errors, outer `catch (e, st)` with `AppLogger.error` for unexpected exceptions. |
| N7 | The outer catch in `DeleteTierAdapter` logs via `AppLogger.error` with both `error:` and `stackTrace:` named arguments and returns `Left(Failure.unknown())`; it never throws. |
| N8 | All UI strings (snackbar texts, dialog text, button tooltip) are accessed via the slang `context.t` accessor; no string literals in widget code. |
| N9 | `DeleteTierState` remains a sealed class generated by freezed; its variants and shape are unchanged by this slice. |
| N10 | The `delete_tier` slice imports nothing from other slices of the `tiers` feature except `_shared/`. |
| N11 | `domain/` layer files import only `dartz`, `freezed_annotation`, and pure Dart packages; no `flutter` or `dio` imports. |
| N12 | `delete_tier` has no route or screen of its own; `DeleteTierButton` is a widget embedded in `tier_details_screen.dart`. |
| N13 | `tiers_api_client.g.dart` is regenerated via `build_runner` after the `deleteTier` annotation change. |

## Out of scope

- Changes to `tier_details` slice beyond the single `DeleteTierButton` call-site line (covered by PRD 0045).
- Changes to `edit_tier` slice (covered by PRD 0046).
- Changing the confirmation dialog wording beyond what is necessary.
- Any modification to `DeleteTierState` variants or the `DeleteTierConfirmationDialog` widget.
